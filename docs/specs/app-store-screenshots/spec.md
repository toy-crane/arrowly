# App Store 스크린샷

## 목적과 승인 범위

Mac에서 슬라이드·차트로 발표하는 사람이 Arrowly로 발표의 핵심을 명확하게 전달할 수 있음을 보여 준다. 소개 본문은 간결하게 유지하고, 주요 기능의 상세 전달은 영어·한국어 스크린샷 각 5장이 맡는다.

사용자는 5장 전체의 한국어 제목, 순서, 기능별 장면과 A안 구도를 승인했다. 이후 직접 만든 슬라이드를 Apple 키노트처럼 더 세련되게 만드는 방향을 요청하고, 밝은 스토어 바깥 배경을 선택했으며 Arrowly의 키 컬러를 적절하게 사용할 것을 요구했다. 기존 연한 파란 배경과 임시 차트 디자인은 최종 디자인으로 사용하지 않는다. 발표 자료와 키 컬러를 적용한 새 시각 디자인은 검토 중이다. 현재 결과물은 구성 참고용이며 실제 앱 캡처나 App Store 등록 완료의 증거가 아니다.

## 관련 소스

- [구성 프로토타입](prototype.html) — 승인한 구도·한국어 제목·기능별 장면을 참고한다. 색상·발표 자료·시각 완성도는 승인 범위가 아니며 새 디자인으로 교체할 예정이다. 가상 주석, 커서와 확대 렌즈는 실제 앱 UI를 대체하지 않는다.
- [구성 미리보기](preview.jpg) — 5장 구성만 참고하며 기존 배경과 차트 스타일을 재사용하는 기준으로 삼지 않는다.
- [유료 판매 스펙](../paid-distribution/spec.md) — 고객층, 핵심 구매 메시지, 언어와 스토어 제출 범위.
- [등록 정보 작업 사본](../paid-distribution/store-listing.md) — 승인한 한국어 소개와 구매 정보, 영문 설명 번역 초안.
- [제품 경계](../../decisions/product-boundary.md) — 스크린샷으로 약속할 수 있는 실제 기능 범위.
- [앱 아이콘](../../../assets/icon.svg), [앱 테마](../../../src/styles.css), [잉크 색상](../../../src/shared/constants.ts) — 실제 브랜드 옐로우·잉크색과 사용 가능한 주석 색의 원본. 기본 그리기 색인 분홍을 브랜드 키 컬러로 혼동하지 않는다.

## 확정된 경험

### 공통 구도

- 상단에 짧은 제목을 두고, 아래에 발표 화면을 크게 보여 주는 A안이다. 같은 내용으로 비교한 좌측 제목·우측 화면 구도 대신 사용자가 최종 선택했다.
- 첫 제목은 기능을 직접 설명하는 문장보다 핵심 전달의 가치를 담은 감성적인 표현을 사용한다.
- 모든 장은 승인한 상단 제목·하단 발표 화면 구도를 따른다. 바깥 배경은 사용자가 선택한 밝은 계열이며, 안쪽 발표 슬라이드의 디자인과 구체적인 키 컬러 적용은 새 시안으로 검토한다. 별도 하드웨어 목업을 추가하지 않는다.
- 키 컬러는 앱 아이콘·테마의 옐로우 계열과 짙은 잉크색에 근거한다. 세부 적용의 에이전트 기본안은 실제 앱 아이콘과 주요 주석에 옐로우를 쓰고 제목 가독성을 유지하는 것이다. 이 적용은 사용자 피드백으로 조정할 수 있다.
- 기능 목록이나 조작 설명을 가득 넣지 않고 각 장에서 하나의 사용 가치를 보여 준다.

### 장별 구성

| 순서 | 한국어 제목 (승인) | 실제 촬영할 장면 | 영문 제목 (번역 기본안) |
|---|---|---|---|
| 1 | 전달할 핵심을, 선명하게. | 분기별 차트에서 중요한 숫자를 동그라미로 강조하고, 화살표와 짧은 메모로 설명한다. | Make your point clear. |
| 2 | 복잡한 흐름도, 한눈에. | 단계가 나열된 슬라이드 위에 화살표로 관계를 연결하고 사각형과 메모로 핵심 단계를 짚는다. | Make complex ideas easy to follow. |
| 3 | 고치고, 설명을 이어가세요. | 차트 위에 놓은 메모를 옮겨 위치를 바로잡는 순간을 보여 준다. 실제 이동 탐색 상태와 커서를 사용한다. | Adjust, then keep explaining. |
| 4 | 새로운 설명이 필요할 때. | 블랙보드 위에 도형·화살표·텍스트로 간단한 관계를 설명한다. | Make room for a new idea. |
| 5 | 작은 디테일까지, 또렷하게. | 발표 슬라이드 속 표의 작은 숫자를 실제 확대 렌즈로 보여 준다. | Bring the details into focus. |

### 캡처 원본

- 현재 출시할 버전의 Arrowly를 실제로 실행해 찍는다. 앱의 플로팅 마커와 확대 렌즈, 커서, 이동 탐색 표시를 시안의 가상 요소로 대체하지 않는다.
- 시안은 배경 슬라이드와 강조할 내용을 준비하는 기준이다. Arrowly로 직접 그린 주석이 포함된 화면을 캡처하며, 캡처 뒤에 주석을 합성하거나 수정하지 않는다.
- 슬라이드·차트·표는 이 작업을 위해 만든 가상 데이터의 영어 데모 자료다. 타사 상표·로고, 실존 인물 정보, 개인 알림이나 파일명이 보이지 않는다.
- 마크의 색·굵기·텍스트 크기는 실제 앱에서 제공하는 값으로 맞춘다.
- 한 장의 정지 화면이 움직임이나 자동 보정을 증명한다고 주장하지 않는다. 3번은 위치 교정 기능을 드러내는 실제 장면이어야 한다.

## 인수 조건

- 영어 5장, 한국어 5장, 모두 2880×1800 PNG이며 투명도가 없다.
- 한국어 제목과 순서가 승인한 표와 일치한다. 영문은 아래 가정의 번역 기본안을 적용한다.
- 제목이 한 줄에 들어가고 축소해도 읽히며, 첫 장에서 화면 위에 그리는 앱임을 알아볼 수 있다.
- 다섯 장 모두 실제 실행 캡처로 해당 기능을 보여 준다. 특히 3번 이동 탐색과 5번 확대 렌즈는 실제 앱의 모습과 일치한다.
- 승인한 시각 구도를 유지하며 실제 촬영을 통해 UI·주석 색상·크기를 구현 가능한 모습으로 맞춘다.
- 타사 상표·로고나 개인정보가 없고, 실제 앱이 제공하지 않는 기능이나 조작을 보여 주지 않는다.
- 제출 단계에서는 App Store Connect 영어(미국)와 한국어 현지화에 각 언어 5장이 위 순서로 올라가 있는 것을 확인한다. 이번 콘셉트 승인은 업로드·심사 제출을 수행한 것으로 보지 않는다.

## 확정된 제약과 비범위

- 실제 사용 화면과 짧은 제목을 결합한 마케팅형, Mac 16:10 규격 2880×1800, 영어·한국어 두 언어다.
- 기능과 앱 UI를 변경하지 않는다. 기능별 조작 설명과 단축키 나열은 스토어 본문에 다시 늘리지 않는다.
- App Preview 영상, 다른 언어, README 이미지 교체, 광고·소셜 미디어 이미지는 범위 밖이다.
- 첫 App Store 심사 게이트와 판매 설정은 유료 판매 스펙이 소유한다.

## 가정

다음은 사용자가 바꿀 수 있는 에이전트 기본값이다.

- 영문 제목은 표의 번역 기본안을 쓴다. 한국어와 같은 가치를 전달하는 번역이며 별도로 사용자 승인받은 문구는 아니다. 새로운 기능이나 구매 약속을 추가하지 않는다.
- 영어판과 한국어판은 같은 실제 캡처를 쓰고 제목만 바꾼다. 배경 데모 자료는 영어다.
- 데모의 구체적인 수치·문구는 가상 데이터이며, 레이아웃과 설명 의도를 유지하는 범위에서 촬영 가독성에 맞게 조정할 수 있다.
- 최종 이미지와 편집기 프로젝트는 저장소 밖에서 관리한다. 승인한 콘셉트 HTML과 미리보기만 이 작업 폴더에 보존한다.
- 실제 화면 캡처 방법은 제작 환경에서 선택한다. 이전 스펙의 "에이전트에게 캡처·조작 권한이 없다"는 가정은 현재 환경에 대한 확인 없이 제약으로 사용하지 않는다.

## 제작 전 확인과 남은 위험

- 실제 Arrowly의 네이티브 조작·캡처 경로는 이번 시안 작업에서 검증하지 않았다. 구현 단계에서 사용 가능한 경로를 확인하며, 자동 조작이 안 되는 부분은 같은 장면 가이드로 사용자가 촬영한다.
- 3번의 위치 교정은 정지 이미지에서 전달력이 약할 수 있다. 실제 캡처에서 대상과 커서를 식별할 수 있는지 확인한다. 전달되지 않으면 장면을 다시 검토하며, 가상의 전후 상태를 실제 캡처처럼 합성하지 않는다.
- 데모 내용이 축소 뒤 읽히지 않거나 원본 해상도가 부족하면 촬영 화면을 조정해야 한다.
- 실제 UI와 시안의 커서·렌즈·색상 세부가 다르면 실제 UI가 기준이다. 이후 앱 UI가 바뀌면 캡처를 갱신한다.
- 영문 제목이 같은 구도에서 자연스럽게 읽히고 잘리지 않는지는 제작 때 확인한다.
