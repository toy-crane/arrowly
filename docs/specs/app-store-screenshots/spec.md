# App Store 스크린샷

## 목적과 승인 범위

Mac에서 슬라이드·차트로 발표하는 사람이 Arrowly로 발표의 핵심을 명확하게 전달할 수 있음을 보여 준다. 소개 본문은 간결하게 유지하고, 주요 기능의 상세 전달은 영어·한국어 스크린샷 각 5장이 맡는다.

사용자는 밝은 스토어 바깥 배경, A안 구도, 직접 만든 발표 자료와 노란색을 포인트에만 쓰는 디자인을 승인했다. 이후 표시 수정 장면 대신 플로팅 마커를 소개하는 장면을 2번에 넣고, 기존 도형 장면을 3번으로 옮겼다. 2번은 흰 슬라이드와 연한 회색 차트 위에 실제 도구 속성 패널을 펼친다. 마커는 오른쪽 아래에 두고 과장하지 않는 크기로 보여 준다. 현재 프로토타입은 제작 기준이다. 사용자는 실제 앱 컴포넌트와 주석 렌더러의 결과를 데모 자료·마케팅 레이아웃에 조합하는 제작 방식을 승인했다. 네이티브 데스크톱 직접 캡처는 필수 조건이 아니며, 이 승인은 App Store 업로드·심사 제출을 포함하지 않는다.

- [유료 판매 스펙](../paid-distribution/spec.md) — 고객층, 핵심 구매 메시지, 언어와 스토어 제출 범위.
- [등록 정보 작업 사본](../paid-distribution/store-listing.md) — 승인한 한국어 소개와 구매 정보, 영문 설명 번역 초안.
- [제품 경계](../../decisions/product-boundary.md) — 스크린샷으로 약속할 수 있는 실제 기능 범위.

## 확정된 경험

### 공통 구도

- 상단에 짧은 제목을 두고, 아래에 발표 화면을 크게 보여 주는 A안이다. 같은 내용으로 비교한 좌측 제목·우측 화면 구도 대신 사용자가 최종 선택했다.
- 첫 제목은 기능을 직접 설명하는 문장보다 핵심 전달의 가치를 담은 감성적인 표현을 사용한다.
- 모든 장은 승인한 상단 제목·하단 발표 화면 구도를 따른다. 바깥 배경은 사용자가 선택한 밝은 계열이며, 2번 발표 슬라이드는 흰 배경, 나머지는 승인한 짙은 배경을 사용한다. 별도 하드웨어 목업을 추가하지 않는다.
- 키 컬러는 앱 아이콘·테마의 옐로우 계열과 짙은 잉크색에 근거한다. 사용자 결정에 따라 노란색은 포인트에만 쓴다. 넓은 배경, 긴 문장, 여러 도형 전체를 노란색으로 채우지 않는다. 구체적인 적용 기본안은 실제 앱 아이콘과 장마다 핵심 한 곳의 동그라미·테두리·밑줄에만 노란색을 남기고, 나머지 주석에는 분홍을 사용하고, 블랙보드는 주황 도형·연결선과 노란 핵심 단어로 따뜻한 톤을 맞춘다. 제목은 짙은 잉크색으로 유지한다.
- 기능 목록이나 조작 설명을 가득 넣지 않고 각 장에서 하나의 사용 가치를 보여 준다.

### 장별 구성

| 순서 | 한국어 제목 (승인) | 제작할 사용 장면 | 영문 제목 (번역 기본안) |
|---|---|---|---|
| 1 | 전달할 핵심을, 선명하게. | 분기별 차트에서 중요한 숫자를 동그라미로 강조하고, 화살표와 짧은 메모로 설명한다. | Make your point clear. |
| 2 | 필요한 도구를, 바로 곁에. | 흰 슬라이드 오른쪽 아래의 플로팅 마커와 펼친 그리기 도구 속성 패널로 도구·색·굵기 선택을 보여 준다. | Your tools, close at hand. |
| 3 | 복잡한 흐름도, 한눈에. | 단계가 나열된 슬라이드 위에 화살표로 관계를 연결하고 사각형과 메모로 핵심 단계를 짚는다. | Make complex ideas easy to follow. |
| 4 | 새로운 설명이 필요할 때. | 블랙보드 위에 도형·화살표·텍스트로 간단한 관계를 설명한다. | Make room for a new idea. |
| 5 | 작은 디테일까지, 또렷하게. | 발표 슬라이드 속 표의 작은 숫자를 실제 확대 렌즈로 보여 준다. | Bring the details into focus. |

### 렌더링 원본

- 현재 저장소의 실제 플로팅 마커·도구 속성 패널·주석 렌더러·확대 렌즈 컴포넌트를 재사용해 사용 장면을 렌더링한다. 앱 소스는 바꾸지 않는다. 설정 저장과 화면 캡처 IPC만 데모 환경의 입력으로 대체하며, 표시되는 UI와 동작 가능한 상태는 실제 구현에 맞춘다.
- 배경 슬라이드·차트·표와 문구는 승인한 디자인을 따른다. 주석은 앱이 지원하는 마크 데이터와 실제 렌더러로 출력한다. 최종 결과는 렌더링 기반 마케팅 이미지이며 네이티브 실행 캡처라고 부르지 않는다.
- 슬라이드·차트·표는 이 작업을 위해 만든 가상 데이터의 영어 데모 자료다. 타사 상표·로고, 실존 인물 정보, 개인 알림이나 파일명이 보이지 않는다.
- 마크의 색·굵기·텍스트 크기는 실제 앱에서 제공하는 값으로 맞춘다.
- 한 장의 정지 화면이 움직임이나 자동 보정을 증명한다고 주장하지 않는다. 2번의 마커와 패널은 앱의 실제 비율을 유지하며 전체 장면의 축척으로 화면 대비 비중을 맞춘다. UI 내부 요소의 상대 크기와 실제 패널 배치를 왜곡하지 않는다.

## 인수 조건

- 영어 5장, 한국어 5장, 모두 2880×1800 PNG이며 투명도가 없다.
- 한국어 제목과 순서가 승인한 표와 일치한다. 영문은 아래 가정의 번역 기본안을 적용한다.
- 제목이 한 줄에 들어가고 축소해도 읽히며, 첫 장에서 화면 위에 그리는 앱임을 알아볼 수 있다.
- 다섯 장 모두 실제 앱 렌더링에 근거한 사용 장면으로 해당 기능을 보여 준다. 특히 2번 플로팅 마커·도구 속성 패널과 5번 확대 렌즈는 실제 앱의 모습과 일치한다.
- 승인한 시각 구도를 유지하고 UI·주석 색상·크기·렌즈 배율과 테두리를 실제 구현에 맞춘다.
- 타사 상표·로고나 개인정보가 없고, 실제 앱이 제공하지 않는 기능이나 조작을 보여 주지 않는다.
- 제출 단계에서는 App Store Connect 영어(미국)와 한국어 현지화에 각 언어 5장이 위 순서로 올라가 있는 것을 확인한다. 이번 콘셉트 승인은 업로드·심사 제출을 수행한 것으로 보지 않는다.

## 확정된 제약과 비범위

- 실제 사용 화면과 짧은 제목을 결합한 마케팅형, Mac 16:10 규격 2880×1800, 영어·한국어 두 언어다.
- 기능과 앱 UI를 변경하지 않는다. 기능별 조작 설명과 단축키 나열은 스토어 본문에 다시 늘리지 않는다.
- App Preview 영상, 다른 언어, README 이미지 교체, 광고·소셜 미디어 이미지는 범위 밖이다.
- 첫 App Store 심사 게이트와 판매 설정은 유료 판매 스펙이 소유한다.

## 가정

다음은 사용자가 바꿀 수 있는 에이전트 기본값이다.

- 영문 제목은 표의 번역 기본안을 쓴다. 한국어와 같은 가치를 전달하는 번역이며 별도로 사용자 승인받은 문구는 아니다. 새로운 기능이나 구매 약속을 추가하지 않는다.
- 영어판과 한국어판은 같은 앱 장면을 쓰고 제목만 바꾼다. 배경 데모 자료는 영어다.
- 데모의 구체적인 수치·문구는 가상 데이터이며, 레이아웃과 설명 의도를 유지하는 범위에서 출력 가독성에 맞게 조정할 수 있다.
- 2번의 크기 기본안은 폭 1000에 대한 실제 폭 251의 마커 비율(약 25%)이며, 우측·하단 여백을 유지한다. 최초 큰 시안에서 줄인 뒤 사용자 요청으로 한 단계(20%) 키운 구도다. 최종 렌더링에서도 상대 비율을 맞춘다.
- 최종 이미지와 편집기 프로젝트는 저장소 밖에서 관리한다. 승인한 콘셉트 HTML과 미리보기만 이 작업 폴더에 보존한다.
- Apple 2.3.3은 앱 사용 장면을 요구하며 문구·이미지 오버레이를 허용한다. 현재 제작 방식의 기준은 [Apple 공식 안내](https://developer.apple.com/help/app-review/guideline-reference/2-3-3-screenshots)와 실제 앱 UI의 일치 여부다. 렌더링 방식 자체가 심사 통과를 보장하지는 않는다.

## 제작 전 확인과 남은 위험

- 네이티브 UI 조회 실패는 승인한 렌더링 제작의 차단 조건이 아니다. 화면 캡처 권한·전체화면 Space 등 네이티브 동작 검증은 이 이미지 제작 결과로 주장하지 않는다.
- 데모 내용이 축소 뒤 읽히지 않거나 원본 해상도가 부족하면 촬영 화면을 조정해야 한다.
- 실제 UI와 시안의 커서·렌즈·색상 세부가 다르면 실제 UI가 기준이다. 이후 앱 UI가 바뀌면 캡처를 갱신한다.
- 영문 제목이 같은 구도에서 자연스럽게 읽히고 잘리지 않는지는 제작 때 확인한다.
