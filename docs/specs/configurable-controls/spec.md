# 조작 키 설정

## 목적

마크 옮기기·복제·삭제 제스처의 수식키, 도구 크기 조절 수식키, 빠른 색 팔레트 키를 사용자가 설정 창에서 바꿀 수 있게 한다.

받아쓰기 앱 Handy처럼 수식키를 누르고 있는 동작을 전역으로 쓰는 앱이 `⌘⌥`를 가로채면 마크 복제가 이동으로 바뀐다. 이 충돌은 2026-11-07과 이번에 두 번 일어났다. 다른 앱의 단축키를 바꾸는 방법만으로는 해결되지 않았다. 사용자가 Arrowly 쪽 키를 바꿔 충돌을 피할 수 있어야 한다.

Esc, 되돌리기 `⌘Z`, 다시 실행 `⇧⌘Z`는 그대로 고정한다. 설정을 잘못 바꿔도 그리기를 빠져나오고 되돌리는 경로는 항상 남아야 한다.

연결 문서:
- [단축키 범위와 소유권](../../decisions/shortcut-policy.md): 무엇을 재설정할 수 있고 무엇을 고정하는지, 마크 제스처 키의 조합 규칙을 정한다.
- [도구와 마크 상호작용 모델](../../decisions/tool-interaction-model.md): 이동·복제·삭제 탐색 상태와 멈춤 규칙을 정한다. 이 작업은 그 규칙을 바꾸지 않고, 규칙에 쓰이는 키를 설정값으로 바꾼다.
- [프로토타입](prototype.html): 승인된 설정 창 화면이다. 그룹 구성·순서·아이콘, 행 배치, 키 필드 모양, 고정 행 표시, 기본값 복귀 방식, 녹화 중 표시와 오류 표시를 이 화면이 정한다. 상단 `state`에서 `복제 키 바꾼 뒤`, `겹침 오류`를 볼 수 있다.

## 설정할 수 있는 조작

| 동작 | 기본값 | 바꿀 수 있는 것 |
|---|---|---|
| 마크 옮기기 | `⌘` 드래그 | 옮기기 키 |
| 마크 복제 | `⌥⌘` 드래그 | 복제 추가 키 (복제 = 옮기기 키 + 복제 추가 키) |
| 마크 하나 지우기 | `⌥` 클릭 | 지우기 키 |
| 도구 크기 조절 | `⌘+` / `⌘−` | 수식키 |
| 빠른 색 팔레트 | `C`를 누른 채 | 키 |

이미 재설정할 수 있는 그리기 시작·끝내기, 블랙보드 켜기·끄기, 마크 모두 지우기, 텍스트 쓰기는 지금의 규칙을 그대로 따른다.

## 마크 제스처 키 규칙

- 옮기기 키와 지우기 키는 각각 수식키 하나다. 고를 수 있는 키는 `⌘`, `⌥`, `⇧`다.
- 옮기기 키와 지우기 키는 서로 달라야 한다.
- 복제는 항상 옮기기 키에 다른 수식키 하나를 더한 조합이다. 복제 추가 키는 옮기기 키와 달라야 하며, 지우기 키와 같아도 된다(기본값이 이 경우다).
- 옮기기 키를 바꾸면 복제 조합도 새 옮기기 키와 기존 복제 추가 키로 함께 바뀐다.
- 규칙을 어기는 조합을 입력하면 저장하지 않고, 그 행 아래에 이유와 해결 방법을 한 줄로 보여준다. 이전 값은 그대로다.
- 탐색 상태 규칙은 [도구와 마크 상호작용 모델](../../decisions/tool-interaction-model.md)을 그대로 따르되 키만 설정값으로 바뀐다.
  - 옮기기 키만 누르면 이동 탐색, 지우기 키만 누르면 삭제 탐색, 옮기기 키와 복제 추가 키를 함께 누르면 복제 탐색이다. 누른 순서는 상관없다.
  - 끄는 도중 복제 추가 키를 떼면 이동, 다시 누르면 복제다. 놓는 순간에 판정한다.
  - 복제 탐색에서 옮기기 키만 먼저 떼서 남은 키가 지우기 키와 같으면 멈춤 상태다. 남은 키가 지우기 키가 아니면 어떤 탐색 상태에도 들어가지 않는다.

## 도구 크기와 빠른 색 팔레트 키

- 도구 크기 조절은 설정한 수식키와 `+`/`−`로 한다. 텍스트 편집 중 텍스트 크기 조절도 같은 수식키를 쓴다.
- 빠른 색 팔레트 키는 수식키 없는 문자 키 하나다. 누른 채 문지르고 놓는 조작은 그대로다.
- 빠른 색 팔레트 키와 텍스트 쓰기 키는 같을 수 없다. 지금 `C`가 텍스트 쓰기에 막혀 있는 자리를, 설정된 팔레트 키가 대신 차지한다.
- Esc, `⌘Z`, `⇧⌘Z`와 이미 지정된 다른 동작의 키는 어느 쪽에도 쓸 수 없다.

## 설정 창

- 설정 창은 [프로토타입](prototype.html)대로 `그리기`, `마크`, `도구`, `고정` 네 그룹으로 나눈다.
  - 그리기: 그리기 시작·끝내기, 블랙보드 켜기·끄기, 마크 모두 지우기
  - 마크: 마크 옮기기, 마크 복제, 마크 하나 지우기
  - 도구: 텍스트 쓰기, 도구 크기 조절, 색 고르기
  - 고정: 되돌리기, 다시 실행, 그리기 끝내기
- 각 행은 왼쪽에 동작 이름, 오른쪽에 같은 폭의 키 필드다. 필드에는 키 기호만 보이고 "드래그"·"클릭" 같은 보조 레이블은 붙이지 않는다.
- 섹션 제목 옆 힌트 문구와 상시 "기본값" 버튼은 없다. 기본값과 다른 행의 필드에 포인터를 올리면 오른쪽 끝에 ✕가 나타나고, 누르면 그 행만 기본값으로 돌아간다.
- 고정 그룹의 키는 필드 상자 없이 흐린 글자로 보여 바꿀 수 없음을 드러낸다.
- 필드를 누르면 녹화 상태가 된다. 수식키 동작(옮기기·복제·지우기·도구 크기)은 수식키를 눌렀다 뗄 때 확정하고, 색 팔레트 키는 문자 키를 누를 때 확정한다. Esc는 녹화를 취소한다.
- 바꾼 값은 저장 즉시 열려 있는 오버레이에 적용되고, 앱을 다시 시작해도 유지된다.

## 온보딩

- 최초 실행 온보딩의 교정 단계(옮기기 → 복제하기 → 지우기 → 되돌리기)는 카드의 키 표시와 실습 판정 모두 현재 설정된 키를 쓴다.

## 인수 조건

- 설정 창이 프로토타입처럼 네 그룹으로 보이고, 기본값 상태에서 마크 옮기기 `⌘`, 마크 복제 `⌥⌘`, 마크 하나 지우기 `⌥`, 도구 크기 조절 `⌘±`, 색 고르기 `C`가 보인다. 고정 그룹에는 되돌리기·다시 실행·그리기 끝내기만 있다.
- 마크 복제 필드에서 `⌘⇧`를 녹화하면 복제가 `⇧⌘`로 바뀌고, 그리기 모드에서 `⌘⇧` 드래그로 마크가 복제된다. `⌘⌥` 드래그는 더 이상 복제가 아니다.
- 마크 복제 필드에 `⌥`만 녹화하거나 옮기기 키가 빠진 조합을 녹화하면 저장되지 않고 오류 문구가 보이며 이전 값이 유지된다.
- 옮기기 키를 지우기 키와 같은 키로 녹화하면 저장되지 않고 오류가 보인다.
- 옮기기 키를 `⇧`로 바꾸면 복제 조합이 `⇧`와 기존 복제 추가 키로 함께 바뀌고, 그리기 모드에서 새 키로 이동·복제가 동작한다.
- 복제 추가 키가 지우기 키와 다른 설정(예: 복제 `⌘⇧`, 지우기 `⌥`)에서 복제 탐색 중 옮기기 키만 떼면 어떤 후보 표시도 나타나지 않고, 그 상태의 클릭은 마크를 지우지 않는다.
- 기본 설정에서 복제 탐색 중 `⌘`만 먼저 떼면 지금처럼 멈춤 상태가 된다.
- 끄는 도중 복제 추가 키를 떼고 놓으면 이동, 다시 누르고 놓으면 복제가 된다(바꾼 키에서도 같다).
- 도구 크기 수식키를 `⌥`로 바꾸면 그리기 중과 텍스트 편집 중 모두 `⌥+`/`⌥−`로 크기가 바뀌고 `⌘+`/`⌘−`는 동작하지 않는다.
- 빠른 색 팔레트 키를 `Q`로 바꾸면 `Q`를 누른 채 문질러 색을 고를 수 있고 `C`는 아무 일도 하지 않는다. 이후 텍스트 쓰기 키에 `Q`를 녹화하면 거부되고 `C`는 허용된다.
- 바꾼 행에 포인터를 올리면 ✕가 나타나고, 누르면 그 행만 기본값으로 돌아간다. 기본값인 행에는 ✕가 나타나지 않는다.
- 설정을 바꾼 뒤 열려 있는 오버레이에서 바로 새 키가 동작하고, 앱을 다시 시작해도 유지된다.
- 온보딩 교정 단계 카드가 현재 설정된 키를 보여주고, 그 키로 각 실습이 완료된다.
- Esc, `⌘Z`, `⇧⌘Z`는 어떤 설정에서도 지금처럼 동작하며, 이 키들을 어느 필드에도 녹화할 수 없다.
- 네이티브: Handy가 `⌘⌥` 누름을 녹음 단축키로 쓰는 상태에서 복제를 `⌘⇧`로 바꾸면, 다른 앱이 활성이고 입력 소스가 한글인 non-activating `NSPanel`에서 복제·`⌘Z`·끄는 도중 `⇧` 해제(이동)와 재입력(복제)이 동작한다. `⇧`의 keydown·keyup이 순서와 관계없이 웹뷰에 도달한다.

## 결정과 근거

- **수식키 충돌은 Arrowly 쪽 설정으로 푼다.** 같은 충돌이 두 번 반복되어 "충돌하는 앱의 단축키를 바꾼다"는 이전 선택의 재검토 조건이 충족되었다. 사용자가 설정 창에서 고를 수 있게 하기로 했다.
- **마크 제스처, 도구 크기, 빠른 색 팔레트를 열고 Esc·되돌리기·다시 실행은 고정한다.** 사용자가 이 범위를 확인했다. 앞의 셋은 다른 앱과 충돌할 수 있는 키이고, 뒤의 셋은 OS 표준이자 탈출·복구 경로라 충돌 이득보다 잘못 바꿨을 때의 위험이 크다.
- **모든 조작을 같은 녹화 방식으로 바꾼다.** 사용자가 마크 제스처 세트 고르기, 키별 세그먼트 버튼과 비교해 골랐다. 제스처 조합 규칙은 녹화 뒤 검증과 오류 문구로 지킨다.
- **설정 창을 그룹 세그먼트로 바꾸고 불필요한 레이블을 뺀다.** 사용자가 레퍼런스 화면을 제시해 정했고, 프로토타입으로 승인했다.

## 가정 (재정의 가능)

- 제스처 수식키 후보에서 `⌃`를 뺀다. macOS에서 `⌃` 클릭은 보조 클릭(우클릭)으로 처리되어 웹뷰에서 드래그·클릭이 의도대로 오지 않을 수 있다.
- 복제 추가 키는 지우기 키와 같아도 된다. 기본값 `⌥⌘`가 이 경우이고, 멈춤 상태 규칙이 이때의 오삭제를 막는다.
- 복제 행의 기본값 복귀는 복제 추가 키만 `⌥`로 되돌리고, 옮기기 행의 복귀는 옮기기 키만 `⌘`로 되돌린다. 복제 조합은 항상 현재 옮기기 키를 따른다.
- 도구 크기 수식키는 수식키 하나 이상의 조합이다. 마크 제스처 키와 겹쳐도 된다. 지금도 `⌘±`와 옮기기 `⌘`가 겹치며, 다른 키를 함께 누르면 탐색이 멈추는 규칙이 이를 처리한다.
- 빠른 색 팔레트 키 후보는 영문자와 숫자 키다.
- 영어 UI 문구는 한국어 승인안과 같은 의미로 맞춘다. 그룹 이름은 Drawing, Marks, Tools, Fixed로 한다.

## 비범위

- Esc, `⌘Z`, `⇧⌘Z`의 재설정: 탈출·복구 경로를 설정이 깨뜨리지 않게 고정한다.
- 플로팅 마커 삭제 버튼(잠금 삭제 도구)과 텍스트 확정 `Enter`·줄바꿈 `⇧Enter`: 충돌 사례가 없고 입력의 기본 규칙이다.
- 다른 앱과의 수식키 충돌 자동 감지: 다른 앱이 수식키 누름을 쓰는지 미리 알 수 없다.
- 마우스 버튼이나 트랙패드 제스처로 조작을 바꾸는 것.

## 남은 위험

- `⇧`를 제스처 키로 쓸 때, 한글 입력 소스에서 `⇧` keydown·keyup이 non-activating `NSPanel` 웹뷰에 빠짐없이 도달하는지는 네이티브로 확인해야 한다.
- 사용자가 고른 새 조합도 다른 앱이 가로챌 수 있다. Arrowly는 이를 감지하지 못하므로, 증상(복제 대신 이동)은 같은 모습으로 다시 나타날 수 있다.
- 키를 자유롭게 바꿀 수 있게 되면서 온보딩·설정 창 외에 키를 고정 문자열로 안내하는 곳이 남아 있으면 실제 키와 어긋난다.
- 이미 출하된 [마크 복제 스펙](../mark-duplicate/spec.md)은 `⌘⌥`를 고정 조작으로 적어 두었고 폴더가 아직 남아 있다. 이 작업과 함께 정리되지 않으면 서로 다른 내용을 말한다.
