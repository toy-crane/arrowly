# 확대 도구 시작 실패 수정

## 연결된 소스

- `docs/specs/magnifier-tool/spec.md` — 확대 도구의 위치, 렌즈 모양, 확대 내용, 상호작용과 화면 기록 권한 계약 전체를 정한다. 이 스펙은 그 계약을 충족하지 못하는 결함을 고치고, 같은 실행 중 재시도할 때의 권한 안내만 구체화한다.
- `docs/decisions/tool-interaction-model.md` — 확대 도구가 잠금 도구로서 다른 도구와 맺는 관계를 정한다.
- `docs/decisions/overlay-presence-and-safety.md` — 확대 중 Esc 탈출, 그리기 모드 한정 동작과 네이티브 검증 범위를 정한다.

## 목적

화면 기록 권한이 허용된 Arrowly에서 확대 버튼을 누르면 확대 렌즈가 실제로 시작되게 한다. 권한을 허용했지만 아직 반영되지 않은 사용자가 같은 안내에 갇히지 않고 재시작으로 빠져나오게 한다.

## 확인한 현재 결함

다음은 별도 표시가 없으면 2026-10-14에 설치된 Arrowly 0.4.0(Developer ID 서명, macOS 26.5.2, 외장 4K 단일 모니터, UI 해상도 1920×1080)에서 관찰한 사실이다.

- 화면 기록 권한이 허용된 상태(TCC `authValue=2`, 서명 요구 조건 일치)에서 새로 시작한 Arrowly의 확대 버튼을 누르면 렌즈 없이 "Magnifier stopped" 안내가 뜬다.
- 시스템 로그상 Arrowly는 권한 확인까지 수행하고 결과는 허용이었다. 그 뒤 화면 캡처 서비스 호출은 한 번도 일어나지 않았고, Arrowly의 오류 출력도 비어 있었다.
- 앱은 확대를 시작하기 전에 오버레이 창의 장치 정보에서 모니터 번호를 읽는다. macOS 창의 장치 정보에는 이 값이 없고 화면의 장치 정보에만 있다. 같은 조건의 시험 패널에서 창 장치 정보의 모니터 번호는 비어 있었고, 그 창이 놓인 화면의 장치 정보에서는 `3`이 나왔다.
- 모니터를 식별하는 단계가 권한 확인 결과와 관계없이 먼저 실패한다. 그래서 권한 유무와 무관하게 모든 시도가 같은 안내로 끝나고, macOS 권한 요청과 재시작 안내도 실제로는 나타나지 않는다.
- 안내 문구가 "권한을 확인하세요"와 "시스템 설정 열기"를 제시하므로 사용자는 권한 문제로 읽는다. 사용자는 이 안내를 보고 시스템 설정에서 직접 권한을 켰지만 동작은 바뀌지 않았다.
- 별도 결함으로, 권한 요청 뒤 같은 실행 중 다시 시도해도 재시작 안내에 도달할 수 없다. 이 항목은 코드의 판정 순서에서 도출했고 실제 화면으로는 확인하지 않았다. 권한 변경이 재시작 뒤에 반영된다는 전제는 아래 가정을 따른다.

## 요구 동작

- 화면 기록 권한이 반영된 상태에서 확대 버튼을 누르면 오버레이가 놓인 모니터를 대상으로 `docs/specs/magnifier-tool/spec.md`의 확대 렌즈가 즉시 시작된다.
- 모니터 식별은 권한 확인 결과를 가리지 않는다. 권한이 없으면 모니터 식별 결과와 관계없이 권한 계약대로 macOS 권한 요청과 권한 필요 안내가 먼저 나타난다.
- 같은 Arrowly 실행 중 화면 기록 권한 요청을 한 번 거친 뒤 다시 확대 버튼을 눌렀는데 여전히 권한이 반영되지 않았다면 재시작 안내를 표시한다.
  - 안내는 권한을 허용했다면 Arrowly를 재시작해야 반영된다는 내용이다.
  - 주 동작은 Arrowly 재시작, 보조 동작은 시스템 설정 열기다.
  - 같은 실행에서 처음 시도할 때는 기존처럼 권한 필요 안내와 시스템 설정 열기만 제공하고 재시작 동작을 보이지 않는다.
- 재시작 뒤 권한이 반영돼 있으면 확대 버튼 한 번으로 렌즈가 시작된다. 재시작이 확대를 자동으로 재개하지는 않는다.
- 권한 거부, 재시작 필요, 서명되지 않은 실행 파일, 그 밖의 캡처 실패를 구분하는 기존 계약은 유지한다.

## 인수 조건

- 권한이 허용된 서명 빌드를 새로 시작하고 그리기 모드에서 확대 버튼을 누르면 `2×` 렌즈와 확대 원본 표시가 커서 주변에 나타나고 렌즈에 아래 화면이 보인다.
- 렌즈가 뜬 상태에서 커서를 움직이면 내용이 따라 갱신되고, 그 사이 "Magnifier stopped" 안내가 나타나지 않는다.
- 권한 기록을 초기화한 서명 빌드에서 처음 확대 버튼을 누르면 macOS 화면 기록 권한 요청이 나타나고, 이어서 권한 필요 안내가 시스템 설정 열기 동작과 함께 나타난다. 이 안내에는 재시작 동작이 없다.
- 같은 실행에서 시스템 설정으로 권한을 켠 뒤 Arrowly로 돌아와 다시 확대 버튼을 누르면 재시작 안내가 나타나고, 재시작 동작과 시스템 설정 열기 동작을 모두 제공한다.
- 재시작 안내에서 재시작을 누르면 Arrowly가 다시 실행되고, 이후 확대 버튼 한 번으로 렌즈가 시작된다.
- 권한을 끈 채 재시작 안내에서 재시작해도 앱이 정상적으로 다시 실행되고, 확대 버튼을 누르면 권한 필요 안내로 돌아간다.

## 네이티브 검증

다음 항목은 모의 테스트로 대체하지 않고 안정적으로 서명된 `Arrowly.app`에서 확인한다.

1. 외장 모니터 단독 구성과 Retina 내장 화면 구성에서 각각 렌즈가 시작되고 원본 위치와 렌즈 내용이 맞는다.
2. 내장 화면과 외장 모니터를 함께 쓸 때, 오버레이가 놓인 모니터의 화면을 확대한다.
3. 최초 권한 요청, 시스템 설정에서 허용, 같은 실행에서 재시도, 재시작, 재시작 뒤 확대 시작까지의 전체 흐름이 위 인수 조건대로 진행된다.
4. 확대 렌즈, 플로팅 마커와 원본 표시가 렌즈 내용에 다시 나타나지 않는다.

## 가정

- macOS는 실행 중인 앱의 화면 기록 권한 확인 결과에 새로 허용한 권한을 앱을 재시작한 뒤에 반영한다. 알려진 동작이며 이번 세션에서 직접 재현하지는 않았다.
- 재시작 안내는 기존 확대 권한 안내의 모양과 배치를 그대로 쓰고 보조 동작 하나만 더한다. 기존 패턴의 확장이라 별도 목업 검토를 생략했다.
- 권한 요청을 거쳤는지는 현재 실행 동안만 기억하고 저장하지 않는다. 재시작하면 다시 첫 시도로 취급한다.
- "권한 요청을 거쳤다"는 macOS 권한 요청을 띄웠거나 안내에서 시스템 설정 열기를 누른 경우를 모두 포함한다.
- 권한과 무관한 캡처 실패는 실패 원인을 구분할 수 있는 진단 기록을 남긴다. 이번 결함이 오류 출력 없이 끝나 원인 추적이 늦어졌기 때문이다. 기록 형식은 구현에서 정한다.

## 비범위

- 확대 렌즈의 모양, 배율, 위치 규칙과 확대 내용 계약 변경
- 실행 중 권한 반영 여부를 재시작 없이 감지하는 방식
- 권한 안내의 색, 재질, 배치 규칙 변경
- 확대 도구의 새 진입 경로나 단축키

## 연기한 결정

- **그 밖의 캡처 실패 안내 문구**: 현재 문구는 권한 확인과 시스템 설정 열기를 권해서 권한과 무관한 실패도 권한 문제로 읽힌다. 문구와 동작을 바꿀지는 별도로 정한다. 그때까지는 기존 문구와 동작을 유지한다(임시).
- **재시작 없이 권한 반영 감지**: 화면 캡처 서비스가 재시작 전에도 새 권한을 반영하는지 확인하지 못했다. 반영된다면 재시작 안내 없이 바로 확대를 시작할 수 있다. 확인 전까지는 위 재시작 안내 동작을 따른다(임시).

## 남은 위험

- 이번 결함이 확대 시작 첫 단계에서 모든 시도를 막았기 때문에, 그 뒤 단계인 Arrowly 자신을 캡처에서 빼는 처리, Retina 배율의 출력 크기, 실시간 갱신 성능은 실제 앱에서 한 번도 실행되지 않았다. 모니터 식별을 고친 뒤 다른 단계에서 새 실패가 드러날 수 있다.
- 재시작 동작은 지금까지 실제 흐름에서 도달할 수 없었으므로 네이티브 동작이 검증되지 않았다.
- 같은 번들 식별자를 쓰는 다른 서명의 빌드(개발 서명, 빌드 폴더의 임시 서명 사본)에 화면 기록 권한을 주면 기존 `/Applications/Arrowly.app`의 권한 기록이 대체될 수 있다. 검증 뒤에는 설치본의 권한 상태를 다시 확인해야 한다.
