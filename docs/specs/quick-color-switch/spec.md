# 빠른 색 선택

## 목적

판서할 위치에서 벗어나지 않고 다음 마크의 잉크 색을 바꾼다. 색마다 키를 외우지 않으며, 조작하는 동안 색이 어떻게 바뀌는지 점 커서와 팔레트에서 계속 보면서 고른다. 견본을 조준해 클릭하는 단계 없이, 수정자 없는 `C`를 누른 채 좌우로 문지르고 놓는 한 동작으로 끝낸다.

이 작업은 출하된 "`C`를 누른 채 견본 클릭" 방식을 대체한다. 팔레트의 모양, 위치 규칙의 기본 틀, 단축키 정책과 잉크 상태 계약은 유지하고, 색을 고르는 기준과 확정 방식만 바꾼다.

연결 문서:
- [단축키 범위와 소유권](../../decisions/shortcut-policy.md): `C`의 소유권과 색별 직접 키를 두지 않는 결정을 따른다.
- [도구와 마크 상호작용 모델](../../decisions/tool-interaction-model.md): 팔레트·단계 수치는 코드와 테스트가 소유한다는 경계를 따른다.

## 빠른 색 팔레트

- 그리기 모드에서 수정자 없는 `C`를 누르고 있는 동안 키를 누른 순간의 포인터 가까이에 [빠른 색 팔레트](../../../GLOSSARY.md)를 연다.
- 빠른 색 팔레트는 도구 속성 패널의 색 선택 줄을 그대로 재사용한다. 옐로우·오렌지·핑크·그린·블루 다섯 색을 같은 순서, 같은 원형 견본, 같은 현재 색 표시로 한 줄에 놓고, 같은 다크 반투명 재질을 쓴다. 원형·방사형 메뉴로 재배치하거나 색 이름·키 배지를 상시 표시하지 않는다.
- 팔레트는 **현재 색 견본이 포인터 바로 위에 오도록** 가로 위치를 맞춘다. 세로로는 포인터 위에 띄우고, 위쪽 공간이 부족하면 아래로 보낸다.
- 어느 경우든 팔레트 전체를 오버레이의 `6px` 안전 여백 안에 둔다. 화면 좌우 가장자리에서 여백 때문에 현재 색 견본을 포인터 위에 둘 수 없으면 팔레트를 여백 안으로 밀어 넣고, 이때 현재 색 견본은 포인터에서 비켜 있을 수 있다.
- 팔레트는 열린 뒤 포인터를 따라다니지 않는다. 포인터 자체도 고정하지 않는다.

## 문지르기로 고르기

- 팔레트를 연 직후 미리보기 색은 현재 색이다. `C`를 누르기만 하고 놓으면 아무것도 바뀌지 않는다.
- 포인터가 처음 있던 견본 열을 가로로 벗어나면, 그때부터 미리보기 색은 포인터의 가로 위치 아래에 있는 견본 열의 색이다. 세로 이동은 미리보기에 영향을 주지 않는다.
- 포인터가 팔레트의 왼쪽 끝 열보다 더 왼쪽에 있으면 옐로우, 오른쪽 끝 열보다 더 오른쪽에 있으면 블루를 미리본다. 블루 다음에 옐로우로 돌아가는 순환은 없다.
- 팔레트가 열린 동안 휠 또는 트랙패드 두 손가락 스크롤을 하면 미리보기 색을 한 칸씩 옮긴다. 끝 색에서는 멈춘다. 이후 포인터가 다른 견본 열로 넘어가면 그 열의 색이 다시 미리보기가 된다.
- 미리보기 색은 팔레트의 강조 셀, 점 커서와 플로팅 마커의 현재 그리기 도구 아이콘에 즉시 반영된다. 팔레트의 현재 색 표시는 확정 전까지 원래 색에 남는다.

## 확정과 취소

- `C`를 놓으면 그 순간의 미리보기 색을 확정하고 팔레트를 닫는다. 별도의 확인 동작이나 토스트는 없다.
- 팔레트가 열린 동안 색 견본을 클릭해도 그 색을 즉시 확정하고 닫는다.
- `Esc`는 팔레트가 열려 있을 때 선택만 취소한다. 원래 색으로 돌아가고 팔레트를 닫으며, 그리기 모드는 유지한다. 이 `Esc`는 그리기 모드 종료로 이어지지 않는다.
- 그리기 모드 종료와 창 포커스·문서 표시 상실은 선택을 취소하고 원래 색을 유지한 채 팔레트를 닫는다.
- 팔레트가 열린 동안 색 견본이 아닌 곳의 포인터 누름은 마크를 시작하지 않고 색도 확정하지 않는다.
- 열린 도구 속성 패널이 있으면 `C`가 이를 닫고 빠른 색 팔레트만 연다. 플로팅 마커의 속성 패널을 열면 빠른 색 팔레트는 선택을 취소하고 닫힌다. 두 색 선택 표면을 동시에 표시하지 않는다.
- 플로팅 마커를 숨긴 상태에서도 `C`로 빠른 색 팔레트를 열 수 있다.

## 잉크와 도구 상태

- 색 변경은 현재 도구, 굵기와 잠금 상태를 바꾸지 않는다. 자유곡선·기하·텍스트·마크 삭제 중 어떤 도구가 활성이어도 이후 만들 마크의 잉크 속성에만 적용된다.
- 미리보기 중에는 어떤 마크의 색도 바뀌지 않는다. 확정한 뒤 만드는 마크부터 새 색을 쓴다.
- 포인터를 누르고 있는 동안에는 `C`를 무시한다. 진행 중 획·기하 미리보기·이동·삭제 제스처의 색과 상태를 바꾸지 않는다.
- 운영체제 키 반복으로 들어오는 추가 `C` keydown은 무시한다. 최초 keydown부터 확정 또는 취소까지를 하나의 선택 세션으로 처리한다.
- 텍스트 편집 세션 중에는 글자 입력이 우선하므로 `C`가 팔레트를 열지 않는다. 새 텍스트의 색은 편집 세션을 시작하기 전에 고른 현재 잉크 색을 따른다.
- 기존 텍스트 마크 교정 중에는 팔레트를 열지 않으며 마크의 원래 색을 보존한다.

## 단축키 정책과 발견성

- `C`는 그리기 모드에서만 쓰는 고정 로컬 키이며 재설정하지 않는다.
- 사용자 설정 텍스트 단축키에는 수정자 없는 `C`를 배정할 수 없다. 수정자가 붙은 `C`는 허용하며, 빠른 색 팔레트는 수정자 없는 `C`에만 반응한다.
- 색별 직접 단축키(`⌘1`–`⌘5`, 색 이름 이니셜 등)는 두지 않는다. 팔레트 안에도 색별 키를 두지 않는다.
- 도구 속성 패널의 색 견본에는 색 이름만 접근성 이름과 툴팁으로 제공한다.
- 설정 창의 `고정 조작`에 있는 `색 고르기 — C` 행은 유지한다.

## 인수 조건

- 자유곡선 도구에서 포인터를 화면 중앙에 두고 `C`를 누르면, 포인터 위에 5색 선택 줄이 열리고 현재 색 견본이 포인터 바로 위에 온다.
- `C`를 누른 채 오른쪽으로 견본 두 칸만큼 움직이면 강조 셀, 점 커서와 플로팅 마커 아이콘이 두 칸 오른쪽 색으로 바뀌고, 위아래로 움직여도 미리보기 색은 바뀌지 않는다.
- 그 상태에서 `C`를 놓으면 팔레트가 닫히고, 다음에 그린 마크만 그 색이 된다. 이전 마크의 색은 그대로다.
- `C`를 눌렀다가 포인터를 처음 견본 열 밖으로 움직이지 않고 놓으면 색이 바뀌지 않는다.
- 미리보기 색을 바꾼 뒤 `Esc`를 누르면 원래 색으로 돌아가 팔레트가 닫히고, 그리기 모드는 유지된다.
- 팔레트가 열린 동안 아래로 스크롤하거나 두 손가락으로 스와이프하면 미리보기 색이 한 칸씩 넘어가고, 블루에서 더 넘겨도 블루에 머문다.
- 화면 왼쪽 끝 가까이에서 현재 색이 블루일 때 `C`를 누르면, 팔레트가 `6px` 여백 안에 보이고 처음에는 블루를 미리본다. 포인터를 오렌지 열로 옮기면 오렌지, 옐로우 열로 옮기면 옐로우를 미리보며 다섯 색 모두에 닿을 수 있다.
- 화면 위쪽에서 `C`를 누르면 팔레트가 포인터 아래로 열린다.
- 팔레트가 열린 동안 견본을 클릭하면 그 색으로 즉시 확정되고, 견본이 아닌 곳을 누르면 마크가 생기지 않는다.
- 기하 도구나 잠긴 마크 삭제 도구에서 색을 바꿔도 현재 도구, 굵기와 잠금 상태가 유지된다.
- 플로팅 마커를 숨겨도 `C`가 팔레트를 열고, 도구 속성 패널과 빠른 색 팔레트는 동시에 보이지 않는다.
- 진행 중 포인터 제스처에서 `C`를 눌러도 팔레트가 열리거나 진행 중 마크가 바뀌지 않는다.
- 새 텍스트와 기존 텍스트를 편집하는 동안 `C`를 입력하면 글자가 입력되고 팔레트는 열리지 않는다.
- `⌘1`–`⌘5`와 `Y/O/P/G/B`는 Arrowly의 색을 바꾸지 않는다.
- 위 동작이 실제 non-activating `NSPanel`에서 한글 입력 소스일 때도 같게 동작한다.

## 결정과 근거

- **문지르고 놓아서 확정한다.** 비교 프로토타입에서 현재 방식(누른 채 견본 클릭), `C` 연타 순환, 누른 채 문지르기를 직접 써 본 뒤 사용자가 문지르기를 골랐다. 색을 외우지 않아도 되고, 조작하는 동안 결과가 계속 보이며, 마우스·트랙패드·펜 어떤 포인터에서도 휠과 같은 효과를 낸다.
- **놓으면 확정한다.** 지난 작업에서 클릭 확정으로 바꾼 데에는 특별한 이유가 없었다고 사용자가 확인했다. 미리보기가 점 커서와 마커에 계속 반영되므로 놓기 전에 결과를 확인할 수 있다.
- **연타 순환은 쓰지 않는다.** 먼 색까지 여러 번 눌러야 하고, 문지르기가 같은 목적을 더 직접적으로 해결한다.

## 가정 (재정의 가능)

- 견본 한 칸의 이동 거리는 견본 셀 간격과 같다. 그래서 화면 가장자리가 아니면 강조 셀이 항상 포인터 바로 위에 있다.
- 끝 색에서 멈추고 순환하지 않는다. 강조 셀이 포인터 위치와 어긋나지 않게 하기 위해서다.
- 스크롤 방향은 아래쪽·오른쪽이 블루 방향이다. 운영체제의 자연스러운 스크롤 설정에 따라 체감 방향이 달라질 수 있다.
- 한 스크롤 단계를 만드는 누적량은 코드와 테스트가 정한다.
- 견본 클릭 확정은 기존 습관과의 호환을 위해 남긴다.

## 비범위

- 색별 직접 단축키, 숫자 키 매핑과 `C` 연타 순환
- 끝 색에서 처음 색으로 돌아가는 순환
- 포인터 고정(Pointer Lock)으로 커서를 제자리에 묶는 방식
- 원형·방사형 메뉴와 `C` 토글 방식
- 빠른 색 팔레트 안의 키보드 탐색
- 색 팔레트와 `C` 키의 커스터마이즈
- 텍스트 편집 세션 중 색 변경과 기존 마크 재색칠
- 5색 팔레트 자체의 변경

## 남은 위험

- 실수로 `C`를 놓아 원치 않는 색이 확정될 수 있다. 미리보기가 보이므로 위험은 작다고 보지만, 실제 강의 흐름에서 오확정이 반복되면 처음 열로 돌아와 놓기를 취소로 처리하는 방안을 다시 검토한다.
- non-activating `NSPanel`에서 수정자 없는 `C`의 keydown·keyup, 팔레트가 열린 동안의 휠·트랙패드 스크롤과 `Esc`가 한글 입력 소스와 플로팅 마커 숨김 상태에서도 안정적으로 웹뷰에 도달하는지 네이티브로 확인한다. keyup을 놓치면 팔레트가 닫히지 않을 수 있다.
- 서로 다른 해상도의 다중 디스플레이와 화면 모서리에서 팔레트 위치 보정이 견본 열과 포인터 위치를 어긋나게 하지 않는지 확인한다.
