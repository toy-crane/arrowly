# 마크 복제

## 목적

강의 중 같은 화살표, 같은 도형, 같은 텍스트 표시를 화면의 다른 곳에 한 번 더 놓을 때 다시 그리지 않는다. 이미 확정한 마크 하나를 끌어서 같은 마크를 새로 놓고, 원본은 그 자리에 그대로 둔다.

복제는 이동 제스처에 `⌥`를 더하는 일회성 포인터 동작이다. 지속적인 선택, 클립보드, 붙여넣기 위치 같은 숨은 상태를 만들지 않는다. Finder·Keynote·Figma의 "끌면 이동, `⌥`를 더해 끌면 복사" 관례와 같은 모양이라 따로 배울 것이 적다.

연결 문서:
- [제품 경계](../../decisions/product-boundary.md): 지속적인 선택 상태와 여러 마크 선택을 두지 않는다는 경계 안에서 마크 하나만 복제한다.
- [도구와 마크 상호작용 모델](../../decisions/tool-interaction-model.md): 복제 탐색 상태, 후보 표시·hit-test 공유, 실행 취소 단위와 `⌘`를 먼저 뗐을 때의 멈춤 규칙을 따른다.
- [단축키 범위와 소유권](../../decisions/shortcut-policy.md): 복제 제스처는 재설정하지 않는 고정 조작이다.
- [프로토타입](prototype.html): 승인된 온보딩 교정 단계 화면이다. 제목·설명 문구, 네 단계 카드의 순서·키 표시·완료 표시, 실습 중 캔버스의 마크 변화를 이 화면이 정한다.

## 복제 탐색 상태

- 그리기 모드에서 `⌘`와 `⌥`가 함께 눌려 있으면 [복제 탐색 상태](../../../GLOSSARY.md)다. 누른 순서는 상관없다.
  - `⌘`를 누른 이동 탐색 상태에서 `⌥`를 더하면 복제 탐색 상태로 바뀐다.
  - `⌥`를 누른 삭제 탐색 상태에서 `⌘`를 더하면 복제 탐색 상태로 바뀐다.
- 복제 탐색 상태는 이동·삭제 탐색 상태와 같은 표시 지연, 같은 후보 표시, 같은 hit-test를 쓴다. 겹친 곳에서는 가장 위의 마크 하나가 대상이다.
- 복제 탐색 상태에서는 포인터가 운영체제 표준 복사 커서(`+`가 붙은 화살표)로 바뀐다. 이동 탐색의 커서와 구별된다.
- 복제 탐색 상태에서 `⌥`만 떼서 `⌘`만 남으면 이동 탐색 상태로 돌아간다.
- 복제 탐색 상태에서 `⌘`만 떼서 `⌥`만 남으면 **멈춤 상태**가 된다. 삭제 후보를 드러내지 않고, 이 상태의 클릭은 마크를 지우지 않는다. 모든 키를 뗀 뒤 `⌥`를 새로 눌러야 삭제 탐색 상태가 된다.
- 복제 탐색 상태에서 다른 키를 함께 누르면 지금의 이동·삭제 탐색과 같이 멈춤 상태가 된다.
- 텍스트 편집 세션 중, 포인터를 누르고 있는 동안, 빠른 색 팔레트가 열린 동안에는 복제 탐색 상태로 들어가지 않는다. 이동·삭제 탐색과 같은 조건이다.
- 플로팅 마커의 삭제 버튼으로 삭제를 잠근 동안에는 `⌘⌥`를 눌러도 복제 탐색 상태로 들어가지 않는다.

## 끌어서 복제하기

- 복제 탐색 상태에서 마크를 누르고 이동 제스처와 같은 임계 거리 이상 끌면 복제 제스처가 시작된다.
- 끄는 동안 원본은 제자리에 그대로 보이고, 원본과 똑같은 복제본 미리보기가 포인터를 따라 움직인다.
- 끄는 도중 `⌥`를 떼면 같은 제스처가 이동으로 바뀌어 원본이 따라 움직이고, 다시 누르면 복제로 돌아간다. 복제인지 이동인지는 **포인터를 놓는 순간** `⌥`가 눌려 있는지로 정한다.
- 끄는 도중 `⌘`를 먼저 떼도 제스처는 취소되지 않는다. 지금의 이동 제스처와 같다.
- 놓으면 원본과 같은 종류·색·굵기·화살촉·텍스트 내용·텍스트 크기를 가진 새 마크가 놓은 위치에 확정된다. 원본은 위치와 z-order가 바뀌지 않는다.
- 복제본은 가장 위에 놓인다. 새로 그린 마크와 같다.
- 놓을 위치에 대한 화면 경계 규칙은 이동 제스처와 같다.
- 임계 거리를 넘기지 않고 놓은 클릭은 아무것도 만들지 않는다. 같은 자리에 겹친 복제본을 만들지 않는다.
- 빈 곳에서 시작한 끌기는 아무것도 만들지 않는다.
- 놓은 뒤에도 `⌘⌥`를 계속 누르고 있으면 복제 탐색 상태가 유지되어, 원본이나 방금 만든 복제본을 다시 끌어 여러 개를 연달아 만들 수 있다.
- 펜·직선·도형·텍스트 마크 모두 복제할 수 있다.

## 실행 취소

- 복제 하나는 실행 취소 한 단위다. `⌘Z`는 방금 만든 복제본만 지우고 원본은 건드리지 않는다. `⇧⌘Z`는 같은 위치·z-order로 복제본을 다시 놓는다.
- 끄는 도중 `⌥`를 떼서 이동으로 끝난 제스처는 마크 이동 한 단위다.

## 발견성

- 설정 창 `고정 조작` 목록에서 "마크 옮기기 `⌘` 드래그" 바로 아래에 "마크 복제 `⌘` `⌥` 드래그" 행을 보여준다.
- 최초 실행 온보딩의 교정 단계에 복제 실습을 넣는다. 순서는 옮기기 → 복제하기 → 지우기 → 되돌리기다.
  - 복제하기 단계는 마크를 `⌘⌥`로 끌어 복제본이 생기면 완료된다.
  - 지우기 단계에서는 화면의 두 마크 중 어느 것을 지워도 완료된다. 되돌리기는 지운 마크를 되살린다.
  - 단계 제목과 설명, 네 단계 카드의 구성은 [프로토타입](prototype.html)을 따른다. 영어 문구는 같은 의미로 맞춘다(가정 참조).
  - 온보딩 전체는 계속 3페이지이며, 교정 페이지 안의 실습만 넷으로 늘어난다.

## 인수 조건

- 펜 마크 하나를 그린 뒤 `⌘`를 누르고 `⌥`를 더한 채 그 마크를 끌면, 원본은 제자리에 남고 같은 모양·색·굵기의 복제본이 포인터를 따라오며, 놓은 자리에 확정된다.
- `⌥`를 먼저 누르고 `⌘`를 더해도 같은 복제가 일어난다.
- 직선(화살촉 포함), 사각형·타원·삼각형, 텍스트 마크도 같은 방법으로 복제되고, 텍스트 복제본은 원본과 같은 내용과 텍스트 크기를 가진다.
- 복제 탐색 상태에서 커서가 복사 커서로 바뀌고, 이동 탐색 상태와 같은 후보 표시가 나타난다.
- 끄는 도중 `⌥`를 떼고 놓으면 원본이 옮겨지고 복제본은 생기지 않는다. 끄는 도중 `⌥`를 다시 누르고 놓으면 복제본이 생긴다.
- 끌기 전에 `⌘`만 떼서 `⌥`만 남은 상태로 마크를 클릭해도 마크가 지워지지 않는다. 모든 키를 뗀 뒤 `⌥`를 다시 누르고 클릭하면 지워진다.
- `⌘⌥`를 누른 채 마크를 클릭만 하면 아무 마크도 생기지 않는다.
- 겹친 마크 위에서 복제하면 가장 위의 마크가 복제되고, 복제본은 모든 마크 위에 놓인다.
- `⌘⌥`를 떼지 않고 두 번 끌면 복제본이 두 개 생기고, `⌘Z` 두 번에 두 복제본이 차례로 사라지며 원본은 남는다.
- 잠긴 마크 삭제 도구 상태에서 `⌘⌥`를 눌러도 복제 탐색으로 바뀌지 않는다.
- 설정 창 `고정 조작`에 마크 복제 행이 마크 옮기기 바로 아래에 보인다.
- 온보딩 교정 단계가 옮기기 → 복제하기 → 지우기 → 되돌리기 순으로 진행되고, 각 단계가 위의 완료 조건으로 넘어간다. 화면의 제목, 설명과 네 카드가 프로토타입과 같고, 640×480 창에서 카드 키 표시가 줄바꿈되지 않는다.
- 온보딩 교정 단계에서 네 실습을 모두 마치기 전에는 `다음`이 비활성이다.
- 위 동작이 실제 non-activating `NSPanel`에서 다른 앱이 활성인 채로, 한글 입력 소스에서도 같게 동작한다. 두 수식키의 keydown·keyup이 순서와 관계없이 웹뷰에 도달한다.

## 결정과 근거

- **`⌘⌥` 끌기로 복제한다.** 사용자가 커서 아래 마크 `⌘D`, 커서 아래 `⌘C` 후 `⌘V`와 비교해 골랐다. 이동 제스처에 키 하나를 더하는 구조라 선택 상태가 없고, macOS 관례와 같다. `⌘D`는 놓은 뒤 다시 옮겨야 하고, `⌘C/⌘V`는 무엇이 담겼는지 보이지 않는 클립보드 상태를 만든다.
- **`⌘`만 먼저 떼면 멈춘다.** 사용자가 삭제 탐색으로 바로 넘어가는 방식보다 이것을 골랐다. 복제하려다 손을 떼는 중에 다음 클릭이 마크를 지우는 사고를 막는다.
- **온보딩에 복제 실습을 넣는다.** 사용자가 설정 창에만 알리는 방식보다 이것을 골랐다. 튜토리얼이 한 단계 길어지는 비용보다 발견성을 우선했다. 화면은 프로토타입으로 확인한 뒤 사용자가 승인했다.

## 가정 (재정의 가능)

- `⌘⌥`의 누른 순서와 관계없이 복제 탐색이 된다. 지금은 먼저 누른 수식키의 탐색이 유지되므로, `⌥`→`⌘` 순서의 동작이 삭제 탐색 유지에서 복제 탐색으로 바뀐다.
- `⌥`만 떼면 이동 탐색으로 돌아간다. 이동은 되돌리기 쉬워 `⌘` 쪽과 같은 보호가 필요하지 않다고 봤다.
- 끄는 도중 `⌥`를 바꾸면 이동과 복제가 오가고, 놓는 순간에 판정한다. Finder와 Figma의 동작을 따랐다.
- 복제 탐색 커서는 운영체제 표준 복사 커서를 쓴다. 후보 표시는 이동 탐색과 같다. 그래서 별도 화면 프로토타입 없이 진행한다.
- 클릭만으로는 복제하지 않는다. 같은 자리에 겹친 복제본은 보이지 않아 실수를 알아채기 어렵다.
- 온보딩 한국어 문구는 프로토타입으로 승인되었다. 영어 문구는 프로토타입에 없으므로 다음을 기본안으로 한다.
  - 제목: "Work with the mark you just drew"
  - 설명: "Move the mark, duplicate it, delete one, then bring it back."
  - 단계 이름: "Duplicate a mark"

## 비범위

- 시스템 클립보드를 쓰는 복사·붙여넣기(`⌘C`/`⌘V`), 다른 앱과의 마크 교환
- `⌘D` 같은 키보드만으로 하는 복제
- 여러 마크를 한 번에 복제하는 동작과 이를 위한 선택 상태
- 복제와 동시에 크기·색을 바꾸는 동작
- 플로팅 마커의 복제 버튼과 잠금 복제 도구
- 모니터 사이의 복제

## 남은 위험

- non-activating `NSPanel`에서 `⌘`와 `⌥`를 동시에 누르고 순서를 바꿔 뗄 때 keydown·keyup이 모두 웹뷰에 도달하는지 네이티브로 확인해야 한다. keyup 하나를 놓치면 복제·멈춤 상태에 갇힐 수 있다.
- `⌥`→`⌘` 순서의 동작 변화로, 삭제하려고 `⌥`를 누른 상태에서 실수로 `⌘`를 건드리면 삭제 대신 복제 탐색이 된다. 실제로 혼란이 반복되면 먼저 누른 키를 우선하는 방식을 다시 검토한다.
- 다른 앱이나 시스템이 `⌘⌥` 끌기를 가로채는지 미리 알 수 없다. 오버레이가 포인터를 소유하는 그리기 모드에서는 영향이 없을 것으로 보지만 네이티브에서 확인한다.
- 온보딩 단계가 하나 늘어 첫 실행 이탈이 늘 수 있다.
