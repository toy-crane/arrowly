# Mac App Store 유료 판매

## 목적

판매를 운영하는 공수를 최소화하기 위해 Arrowly를 Mac App Store에서 $14.99 일회성 유료 앱으로 판매한다. 첫 제출을 심사 게이트로 삼아 현재 투명 오버레이가 심사를 통과하는지 확인하고, 통과하지 못하면 앱을 다시 만들지 않고 Polar 직판으로 판매한다.

## 관련 소스

- [docs/decisions/paid-distribution.md](../../decisions/paid-distribution.md) — App Store 우선과 심사 게이트, 게이트 실패 시 Polar 직판, 앱의 구매 비확인, 저장소·설치 파일 공개 범위의 기준.
- [docs/decisions/overlay-presence-and-safety.md](../../decisions/overlay-presence-and-safety.md) — 샌드박스 빌드에서도 유지해야 하는 메뉴바 유틸, 비활성 패널, 탈출 경로.
- [docs/decisions/shortcut-policy.md](../../decisions/shortcut-policy.md) — 샌드박스 빌드에서도 유지해야 하는 전역 단축키 동작.
- [docs/decisions/product-boundary.md](../../decisions/product-boundary.md) — 앱 기능 범위. 이 작업은 앱 기능을 바꾸지 않는다.
- 게이트 실패 시 Polar 직판 계약: 커밋 `d9b94a8`의 `docs/specs/paid-distribution/spec.md`.
- [docs/specs/app-store-screenshots/spec.md](../app-store-screenshots/spec.md) — 스토어 스크린샷. 심사 제출 전에 끝나야 한다.

## 1단계: 심사 게이트

- 첫 제출 빌드는 현재 출시 버전의 기능 전체와 투명 오버레이를 그대로 담은, 그대로 판매할 수 있는 빌드다. 게이트를 통과하면 별도 심사 없이 판매를 시작할 수 있어야 한다.
- 제출은 수동 출시로 설정해 승인되더라도 바로 공개되지 않게 한다.
- 게이트 판정은 다음 셋으로 나눈다.
  - 통과: App Review가 승인해 제출 빌드가 개발자 출시 대기(Pending Developer Release) 상태가 된다.
  - 실패: 업로드 검사가 비공개 API 사용(ITMS-90338)으로 거부하거나, 심사가 지침 2.5.1(공개 API만 사용)로 거절하거나, 아래 "샌드박스 빌드의 동작" 중 하나를 샌드박스에서 공개 API로 유지할 수 없다고 확인된다.
  - 재제출: 메타데이터, 스크린샷, 개인정보 항목, 로그인 항목 동의, 샌드박스 권한 설정처럼 오버레이 구현을 건드리지 않고 고칠 수 있는 거절은 고쳐서 다시 제출하며 게이트 실패로 보지 않는다.
- 게이트가 진행되는 동안 지금의 무료 DMG 배포와 README는 바꾸지 않는다.

## 2단계: 판매 시작 (게이트 통과 시)

- 수동 출시로 App Store 판매를 시작하고, App Store 상품 페이지에서 구매할 수 있는 것을 확인한 뒤에 공개 설치 파일을 내리고 README를 바꾼다. 앱을 얻을 경로가 하나도 없는 시점을 만들지 않는다.
- v0.1.0-beta부터 현재 버전까지 모든 공개 GitHub Release의 설치 파일 에셋(DMG, 앱 압축본)을 내린다. 릴리스 항목과 변경 내역은 남긴다.
- README 첫 화면의 다운로드 링크 자리에 Mac App Store 링크, 가격($14.99), 일회성 구매, 이후 업데이트 포함을 보여 준다. 설치 안내는 App Store 설치로 바꾸고, 소개·기능·조작 안내·이슈 링크·개발 안내는 유지한다.

## 게이트 실패 시

- App Store 진입을 멈추고, 오버레이를 다시 만들지 않는다.
- 커밋 `d9b94a8`의 Polar 직판 스펙을 이 폴더에 복원해 그 계약대로 판매한다. 게이트 실패 사유와 근거는 결정 계약의 근거 항목에 남긴다.
- Polar 직판 빌드는 지금의 Developer ID 서명·공증 빌드다. 샌드박스 대응 중 사용자 동작을 바꾸지 않는 변경은 남겨도 된다.

## 확정된 경험

### 구매자

- Mac App Store에서 Arrowly를 찾거나 README 링크로 들어가 $14.99에 구매하고 설치한다. 이후 업데이트는 App Store가 추가 결제 없이 제공한다.
- 판매를 시작한 뒤에는 공개된 곳 어디에서도 설치 파일을 직접 받을 수 없다.
- 앱 안에는 구매·라이선스·체험 기간 관련 화면, 입력, 안내가 없고 구매 영수증을 확인하지 않는다.

### 샌드박스 빌드의 동작

App Store 빌드는 지금의 Developer ID 빌드와 같은 사용자 동작을 유지한다.

- 메뉴바 유틸로 동작하고 평소 Dock과 앱 스위처에 나타나지 않는다.
- 그리기 시작·끝내기, 블랙보드, 전체 지우기, 텍스트 전역 단축키와 그리기 중 Esc 탈출이 동작한다. 단축키 재설정과 충돌 검증도 지금과 같다.
- 오버레이가 전체화면 Space 위에도 나타나고, 그리는 동안 아래 앱은 활성 상태를 유지하며, 메뉴바를 덮지 않는다.
- 확대 도구는 화면 기록 권한을 받은 뒤 현재 화면을 확대한다. 권한 요청, 재시작 안내, 거부·철회 안내는 지금과 같다.
- 단축키와 마커 숨김 같은 사용자 설정이 재실행 뒤에도 유지된다.
- 로그인 시 실행은 기본으로 꺼져 있고, 사용자가 메뉴바에서 켤 때만 등록된다. 켜고 끈 결과가 macOS 로그인 항목에 반영된다.

### 기존 무료 사용자

- 이미 받은 v0.4.0 이하 사본은 계속 동작한다. 별도 안내, 비활성화, 회수는 하지 않는다.
- App Store 버전은 설정 저장 위치가 달라 기존 설정을 이어받지 않는다. 처음 실행하면 튜토리얼과 기본 단축키부터 시작한다.

### 릴리스 담당자

- 새 버전은 App Store용 샌드박스 빌드를 업로드하고 심사를 거쳐 출시한다.
- 공개 GitHub Release는 설치 파일 없이 변경 내역만 보여 준다.
- 릴리스 안내 문서와 릴리스·게시 절차가 App Store를 배포 대상에서 제외하거나 DMG를 공개 게시한다고 적은 부분은 이 계약으로 대체된다.

## 인수 조건

### 게이트

- App Store Connect에 macOS용 Arrowly 앱 레코드가 있고, 현재 버전의 샌드박스 빌드가 업로드 검사를 통과해 수동 출시로 심사에 제출된다.
- 게이트 결과가 통과(개발자 출시 대기) 또는 실패 중 하나로 확정되고, 실패면 업로드 검사나 심사 거절 문구가 기록된다.
- 게이트가 끝나기 전까지 공개 GitHub Releases의 설치 파일과 README 다운로드 링크가 그대로다.

### 샌드박스 빌드 (실제 macOS, App Store 배포용 서명 빌드)

- "샌드박스 빌드의 동작"의 각 항목을 실제 macOS에서 확인한다. 전체화면 Space, 포커스 유지, 전역 단축키, 메뉴바, IME와 포인터 전달은 모의 테스트로 대체하지 않는다.
- 화면 기록 권한이 없는 상태에서 확대 도구를 켜면 권한 요청과 재시작 안내가 나오고, 재시작 뒤 확대 렌즈가 현재 화면을 보여 준다.
- 메뉴바에서 로그인 시 실행을 켜면 시스템 설정의 로그인 항목에 Arrowly가 나타나고, 끄면 사라진다. 새로 설치한 직후에는 꺼져 있다.
- 앱 실행 중 네트워크 요청이 없다.

### 판매 시작

- 미국 스토어에서 $14.99 유료 앱으로 표시되고, 영어와 한국어 설명, Mac 스크린샷, "데이터 수집 안 함" 개인정보 항목을 보여 준다.
- App Store에서 구매·설치한 앱이 실행되고 첫 사용 튜토리얼이 시작된다.
- 공개 GitHub Releases 전체에서 `.dmg`와 `.app.tar.gz` 에셋이 0개다.
- README에 Mac App Store 링크, 가격, 일회성 구매, 업데이트 포함이 보이고, 설치 파일을 직접 내려받는 링크가 없다.

## 확정된 제약

- 가격은 USD $14.99 일회성이다. 기능을 갖춘 발표용 주석 앱이 $12.99–$14.99에 모여 있다(Presentify, Annotate Screen, Keystroke Pro, Cursor Pro, SketchMouse, 2026-10-14 확인). 다른 국가 가격은 App Store의 자동 환산을 따른다.
- 구매자는 국내외 모두다.
- 앱은 라이선스·영수증을 확인하지 않는다. 이유는 결정 계약을 따른다.
- 게이트가 실패하면 오버레이를 다시 만들지 않고 Polar 직판으로 간다.
- 샌드박스 대응은 기존 결정 계약의 사용자 동작을 바꾸지 않는 범위에서만 한다.
- App Store 빌드의 번들 ID는 `com.oddcorp.arrowly`다. 같은 팀의 다른 앱(`com.oddcorp.*`)과 이름 규칙을 맞추며, 등록 뒤에는 바꿀 수 없다. App Store 버전은 샌드박스 때문에 어차피 기존 설정을 이어받지 않으므로 식별자 변경으로 사용자가 추가로 잃는 것은 없다.
- 유료 앱(선결제)으로 판매한다. 무료 앱에 인앱 구매로 기능을 여는 방식은 StoreKit 연동이 필요하고, 출시 뒤 바꾸면 기존 구매자를 영수증으로 구분하는 코드가 필요해 되돌리기 비싸다.
- 스토어 표시 이름은 `Arrowly: Draw on Screen`이다. `Arrowly`는 다른 개발자가 이미 쓰고 있다. 설치된 앱과 메뉴바 이름은 `Arrowly`로 유지한다. App Store Connect 앱 레코드(SKU `arrowly-macos`)는 이 이름으로 만들어져 있다.
- 첫 App Store 버전은 1.0.0이다.
- 카테고리는 주 생산성, 보조 교육이다.
- 스토어 기본 언어는 영어(미국)이고 한국어 현지화를 함께 둔다.
- 개인정보 처리방침과 지원 URL은 GitHub 저장소에 둔다. 처리방침은 데이터를 수집하지 않는다는 문서 하나이고, 지원은 저장소 Issues로 연결한다.
- 스크린샷은 실제 앱 화면에 짧은 문구를 얹은 마케팅형으로 만든다(Mac 2880×1800).
- 빌드 업로드와 심사 제출은 App Store Connect API 키와 CLI로 한다.
- 심사 연락처는 App Store Connect의 앱 심사 정보에 둔다. 저장소에는 기록하지 않는다.

## 가정

다음은 사용자가 바꿀 수 있는 에이전트 기본값이다.

- App Store만 판매 채널로 둔다. 게이트를 통과하면 Polar 직판을 함께 운영하지 않는다.
- 판매 국가는 App Store가 지원하는 전체 국가다.
- 스토어 설명은 README의 소개 문구와 기존 데모 이미지를 바탕으로 쓴다.
- 기존 사용자 설정은 App Store 버전으로 옮기지 않는다.
- Developer ID 서명·공증 빌드 경로는 내부 검증과 게이트 실패 대비용으로 유지하되 공개 게시하지 않는다.

## 비범위

- StoreKit, 인앱 구매, 영수증 검증, 체험판, 구독 — 결정 계약과 가정에 따라 제외한다.
- 오버레이의 네이티브 재작성 — 게이트 실패 시에도 하지 않는다.
- 게이트 통과 뒤 Polar 직판 병행.
- 별도 웹사이트나 랜딩 페이지.
- 할인, 교육 가격, 번들.
- 앱 기능 변경과 기존 무료 사본 회수·공지.
- 광고와 유입 확대 활동. 스토어 설명과 스크린샷 작성은 범위 안이다.

## 보류한 결정

- 유료 메이저 업그레이드: 보류 동안(interim) 모든 이후 버전을 같은 구매에 포함한다. 유료 업그레이드는 결정 계약의 재검토 조건이 충족될 때 정한다.
- 판매 시작 뒤 업데이트가 비공개 API로 거절될 때의 대응: 보류 동안(interim) 해당 업데이트 출시를 멈추고 이전 승인 버전으로 판매를 유지한다. 실제로 발생하면 결정 계약을 재검토한다.
- 기존 무료 사용자 대상 할인: 보류 동안(interim) 없다. 요청이 반복되면 정한다.

## 남은 위험

- 게이트 실패: 웹뷰의 `drawsBackground`와 `fullScreenEnabled` 두 비공개 설정이 지침 2.5.1에 걸릴 수 있다. 같은 상황의 Tauri 앱 사례는 찾지 못했고, Electron 앱이 프레임워크 내부의 비공개 API로 자동 심사에서 거절된 선례가 있다. 실패하면 샌드박스 대응과 스토어 준비에 들인 공수 일부가 버려진다.
- 게이트를 통과해도 이후 업데이트 심사에서 같은 이유로 거절될 수 있다. 당시 Electron 사례에서도 집행이 일관되지 않았다.
- 샌드박스에서 전역 단축키, 비활성 패널, 전체화면 Space 위 표시, 화면 기록이 지금처럼 동작하는지 아직 확인하지 않았다.
- 화면 기록 권한은 서명 신원 기준으로 기억되므로, App Store 서명 빌드에서 권한 흐름을 다시 검증해야 한다.
- 번들 ID가 다른 무료 사본(`com.toycrane.arrowly`)과 App Store 버전이 Applications에서 같은 이름으로 부딪힐 때 설치가 어떻게 동작하는지 확인하지 않았다. 두 앱이 함께 실행되면 전역 단축키가 충돌할 수 있다.
- 체험판이 없어 구매 전환이 낮을 수 있다. 환불은 Apple 정책을 따른다.
- 영수증을 확인하지 않으므로 앱 복사본의 실행을 막지 않는다.
- 업데이트마다 심사를 기다려야 한다.
- 릴리스별 다운로드가 1–3회 수준이라 App Store 노출이 있어도 구매가 없을 수 있다.
- App Store 판매 수익의 국내 매출 처리와 통신판매업 신고 필요 여부를 확인하지 않았다.

## Setup before implementation

- Apple Developer 계정 소유자의 유료 앱 계약(Paid Applications Agreement) 수락과 은행·세금 정보 등록 — 유료 판매와 정산 — App Store Connect의 계약 화면에서 유료 앱 계약이 활성 상태로 표시된다.
- App Store 소규모 사업자 프로그램 등록 — 수수료 15% 적용 — 등록 승인 상태가 확인된다.
- Apple Distribution 인증서, Mac Installer Distribution 인증서, `com.oddcorp.arrowly`용 Mac App Store Connect 프로비저닝 프로필 — 샌드박스 빌드 서명과 업로드 — `security find-identity -v`에 두 인증서가 보이고 개발자 포털에서 프로필이 유효로 표시된다.
- App Store Connect의 macOS용 Arrowly 앱 레코드(`com.oddcorp.arrowly`) — 게이트 제출 — App Store Connect 앱 목록에 Arrowly가 나타난다.
- App Store Connect API 키(App Manager 권한) — CLI 업로드와 심사 제출 — App Store Connect 통합 화면에 활성 API 키가 있다.
- 국내 세무 확인 — App Store 판매 수익 처리와 통신판매업 신고 필요 여부 — 세무 대리인의 답변을 받았거나 필요한 신고를 마친 상태다.
