# 단축키 범위와 소유권

## Decisions

- 그리기 토글과 블랙보드 토글만 상시 전역 등록한다. 전체 지우기와 텍스트 진입은 그리기 모드에서 오버레이가 처리한다.
- 그리기, 블랙보드, 전체 지우기, 텍스트, 마크 옮기기·복제·삭제 제스처의 수식키, 도구 크기 수식키와 빠른 색 팔레트 키는 사용자가 재설정할 수 있다. Esc, Undo/Redo와 삭제 도구는 고정 조작이다.
- 마크 제스처 키는 한 조합 규칙으로 묶인다. 옮기기 키와 지우기 키는 서로 다른 수식키 하나이고, 복제는 항상 옮기기 키에 다른 수식키 하나를 더한 조합이다. 복제 추가 키는 지우기 키와 같아도 된다. 기본값은 옮기기 `⌘`, 복제 `⌥⌘`, 지우기 `⌥`다.
- 전역 단축키에는 수식키가 필요하다. 오버레이가 처리하는 로컬 텍스트 단축키와 빠른 색 팔레트 키는 수식키 없는 키를 허용한다.
- Esc와 표준 `⌘Z` 계열, Arrowly 고정 조작과 내부 중복 조합은 사용자 단축키로 허용하지 않는다. 빠른 색 팔레트 키(기본 `C`)는 텍스트 키로 쓸 수 없으며, 텍스트에 `C`를 쓰던 기존 설정은 기본 텍스트 키로 마이그레이션한다. `E`는 더 이상 예약하지 않는다.
- 잉크 색은 색별 직접 키 없이 빠른 색 팔레트 키를 누른 채 좌우로 문지르고 놓아서 고른다. 사용자가 색마다 키를 외우지 않고, 조작하는 동안 바뀌는 색을 보면서 고르게 하기 위해서다.
- 전역 등록 실패는 조용히 무시하지 않고 해당 설정에서 원인과 해결 방법을 보여준다.

## Why

화면 밖에서도 진입해야 하는 동작만 전역으로 소유하면 다른 앱과의 충돌 범위를 줄일 수 있다. 탈출과 복구에 쓰는 Esc와 OS 표준 Undo/Redo를 고정하면 설정을 잘못 바꿔도 빠져나오고 되돌리는 경로가 남는다.

마크 제스처·도구 크기·색 팔레트 키는 처음에 고정했지만, 받아쓰기 앱이 `⌘⌥` 누름을 가로채 복제가 이동으로 바뀌는 충돌이 반복되었다. 다른 앱의 수식키 사용은 미리 감지할 수 없으므로 사용자가 Arrowly 쪽에서 피할 수 있게 열었다. 제스처 키를 조합 규칙으로 묶는 것은 "이동 제스처에 키 하나를 더하면 복제"라는 구조와 멈춤 규칙이 어떤 키에서도 성립하게 하기 위해서다.

## Boundaries

- 기본 accelerator와 검증 규칙의 실행 가능한 단일 소스는 `src-tauri/src/shortcut_policy.rs`다.
- 설정 스키마와 마이그레이션은 `src/shared/settings.ts`와 `src-tauri/src/store.rs`를 함께 바꾼다.
- 다른 앱 내부 단축키와의 의미 충돌은 미리 감지할 수 없다.

## Reconsider when

- 반복적인 실제 충돌 데이터가 현재 기본값이나 고정 키를 부적절하게 만든다.
- macOS가 앱 비활성 상태의 로컬 키 전달 또는 전역 단축키 등록 방식을 바꾼다.

## Still-rejected alternatives

- 모든 판서 동작을 상시 전역 단축키로 등록하는 방식
- Esc와 Undo/Redo까지 사용자 설정으로 여는 방식: 설정이 탈출·복구 경로를 깨뜨릴 수 있다.
- 다른 앱과의 수식키 충돌을 상대 앱의 단축키 변경으로만 푸는 방식: 같은 충돌이 반복되었다.- 접근성 이벤트 탭으로 다른 앱의 키 입력을 가로채는 방식
- 색별 직접 단축키(`⌘1`–`⌘5`, 색 이름 이니셜): 출하 후 제거했다. 외워야 하고 누르기 전에 결과를 볼 수 없다.
- `C` 연타로 다음 색 순환: 먼 색까지 여러 번 눌러야 해서 비교에서 문지르기에 밀렸다.
