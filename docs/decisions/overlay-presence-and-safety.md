# 오버레이 존재 방식과 탈출 안전

## Decisions

- Arrowly는 평소 Dock과 앱 스위처에서 숨는 메뉴바 유틸이다. 온보딩이나 설정 같은 일반 창이 열릴 때만 Dock에 나타난다.
- 그리기 모드의 비활성 패널은 아래 앱을 활성 상태로 유지하면서 현재 화면의 입력을 소유한다. 통과 모드에서는 오버레이를 숨기고 포인터 입력을 아래 앱에 돌려준다.
- 오버레이 창은 메뉴바를 덮지 않는다. 메뉴바는 전역 단축키와 별개인 상시 탈출·제어 경로다.
- 편집 세션이 없을 때 Esc는 웹뷰와 독립된 Rust 전역 경로로 통과 모드에 들어간다. 텍스트 편집 중 첫 Esc는 내용을 확정하고 편집 세션만 끝내며, 다음 Esc가 그리기 모드를 끝낸다. 웹뷰가 첫 Esc를 처리하지 못해도 다음 Esc는 탈출해야 한다.
- 그리기 진입과 탈출에 필요한 전역 단축키를 확보하지 못하면 그리기 모드에 들어가지 않고 이유를 알린다.
- 블랙보드는 별도 작업 모드나 페이지가 아니라 그리기 모드에 결합되는 불투명 검정 배경 상태다. 투명 배경과 같은 마크 집합을 사용한다.

## Why

화면 전체를 덮는 앱은 정상 기능보다 사용자가 언제든 아래 앱으로 돌아갈 수 있다는 보장이 먼저다. 메뉴바·전역 Esc·비활성 패널을 서로 독립된 경로로 유지하면 웹뷰나 단축키 한 부분이 실패해도 수업 화면을 가두지 않는다. 블랙보드를 배경 상태로 두면 설명을 이어 가면서 별도 문서 상태를 만들지 않는다.

## Boundaries

- 실제 NSPanel, 전체화면 Space, 포커스 유지, 메뉴바 접근, 포인터 전달과 웹뷰 무응답 탈출은 브라우저 모의 테스트로 대체하지 않는다.
- 모니터 구성 변경과 잠자기 복귀 뒤 오버레이를 현재 화면에 다시 맞추고 무효한 화면 좌표의 마크를 남기지 않는다.

## Reconsider when

- macOS가 비활성 패널이나 전역 단축키의 보안·포커스 모델을 바꾼다.
- 메뉴바를 사용할 수 없는 환경에서 별도의 신뢰할 수 있는 탈출 표면이 필요하다는 증거가 생긴다.

## Still-rejected alternatives

- 메뉴바와 Dock 위까지 덮는 더 높은 창 레벨
- 접근성 이벤트 탭으로 모든 키를 가로채는 방식
- 통과 모드에서 보이는 오버레이
- 화이트보드, 반투명 보드와 여러 블랙보드 페이지
