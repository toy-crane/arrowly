# 포인터 핑의 임의 배경 대비

## Decisions

- 포인터 핑의 중심과 링은 어두운 바깥 가장자리와 밝은 안쪽 가장자리를 함께 가져 어느 배경에서도 둘 중 하나가 대비를 만든다.
- 이 두 겹 가장자리는 사용자가 색과 배경을 고를 수 없는 일시적 강조에만 적용한다. 사용자가 잉크색을 바꿀 수 있는 확정 마크의 외곽선 규칙으로 일반화하지 않는다.
- 투명 웹뷰 아래의 배경 픽셀을 읽어 핑 색을 적응시키지 않는다.

## Why

단일 색이나 한 방향 가장자리는 임의 배경에서 대비를 보장할 수 없다. 핑은 색 설정도 없고 실패했을 때 다른 색으로 다시 그릴 수도 없으므로 스스로 밝고 어두운 인접색을 모두 가져야 한다.

## Boundaries

- 이 계약은 핑의 대비 메커니즘만 소유한다. 반경, 수명, 선 두께와 애니메이션 타이밍은 코드와 테스트가 소유한다.
- 동작 줄이기에서도 공간 확장은 생략할 수 있지만 밝고 어두운 가장자리의 대비는 유지한다.

## Reconsider when

- macOS 오버레이가 아래 앱의 실제 배경색을 안정적이고 저비용으로 제공한다.
- 사용자 설정이 핑 색이나 배경을 직접 통제하도록 제품 범위가 바뀐다.

## Still-rejected alternatives

- 단일 고정색, 그림자 하나 또는 밝고 어두운 가장자리 중 하나만 사용하는 방식
- 핑의 가독성 문제를 전체 마크 외곽선으로 해결하는 방식
- 아래 앱 화면을 캡처해 매 프레임 대비색을 계산하는 방식

## Evidence worth preserving

- 옐로우 `#FFD400`은 흰 배경에서 약 `1.4:1`, 핑크 `#FF2D95`도 흰 배경에서 약 `3.3:1`이며 중간 회색에서는 다시 대비가 무너진다.
- macOS 포인터와 Windows 포커스 표시는 서로 반대 밝기의 두 색을 겹쳐 임의 배경 문제를 피한다.
- 투명 웹뷰는 아래 앱 픽셀을 직접 볼 수 없어 배경 적응 방식의 입력을 얻지 못한다.
